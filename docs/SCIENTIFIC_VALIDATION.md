# 科研验证协议

## 目标

本协议用于区分“程序内部一致”与“真实田间有效”。只有完成下列外部验证后，结果才能用于论文定量结论或受控田间试验。

## 数据集分层

1. **金标准小样本**：裁剪后的真实 GeoTIFF、固定 CRS、人工核验行带和预期坐标，用于每次版本回归。
2. **跨工况样本**：不同田块、生育期、飞行高度、光照和含水状态。
3. **失败样本**：无 CRS、错误仿射、NoData、四波段、行带断裂、严重粘连和田头不足。
4. **外场执行样本**：规划路径、终端接收文件、RTK 实际轨迹和作业后碾压调查。

原始数据不进入 Git；应单独保存只读数据，并维护文件 SHA-256、采集日期、设备、飞行参数和授权信息。

## 坐标准确性

- 无 GCP/RTK 时只报告 GeoTIFF 自带配准下的内部一致性，不报告绝对定位精度。
- 有控制点后，分别报告平面 RMSE、最大误差、95% 分位误差和异常点处理规则。
- 软件当前 `$PATH` 输出为 `EPSG:4326`、`lat,lon`、0 基点索引；在目标导航终端中逐项核对终端要求是否一致。
- 核对 `$PATH` 前缀、路线编号、点总数、状态码、记录终止符和末尾 `$INFM` 记录，不得只验证文件能否打开。
- 导入后抽查起点、终点和至少一个转弯点，确认终端显示位置与软件导出坐标一致。
- 明确车辆参考点是 GNSS 天线、机身中心还是作业控制点，并记录对应偏移。
- 只有离线导入、位置比对和人工审核通过后，才允许进行具备紧急停机条件的低速受控试跑。

## 二维农机足迹模型

- `planar_rigid_footprint_v2` 的路径参考点固定为两条履带接地区域的几何中心。
- 预计碾压率使用左右履带有限长度有向矩形的路径扫掠并集与主体、田头已确认作物像素并集的真实交叠；任何田头权重不得进入该物理比例。作物掩膜几何覆盖率使用具有实测前置距离的横向有效割幅线段扫掠并集。
- 回归实验必须记录有效割幅、割刀前置距离、履带宽度、履带中心距、履带接地长度、轴距、姿态采样间隔和验证栅格分辨率。
- 作物掩膜几何覆盖率不包含倒伏、割茬高度、拨禾喂入、落粒和漏割损失，不得作为实际收获率或产量指标。
- 候选策略比较先排除硬约束失败路径；其余路径先比较独立的农业损伤代价，再比较不加权的全田预计碾压率。农业损伤代价必须同时报告主体和田头履带重叠面积；没有主体/田头碾压对照产量数据时，田头权重固定为 `1.0`。
- 若标定低于 `1.0` 的田头权重，必须记录主体未碾压、主体碾压、田头未碾压和田头碾压样方的第二季单位面积产量、样本量、估计方法、置信区间和路径排序敏感性。无掩膜区域不得仅凭模型输出自动认定为无作物道路。
- 动画姿态与足迹栅格化使用同一条分段路径、同一航向窗口和同一倒车方向规则；抽查直线、折点和倒车段的显示姿态与离线姿态数据。
- 播放倍率不是农机速度。试验记录分别保存配置的作业、转弯、进出场速度和用户播放倍率。
- 该结果只表示二维影像平面中的几何重叠，不等于真实土壤压实率或完整车辆动力学结果。

## 模型验证

- 固定训练/验证/测试划分及其版本哈希。
- 记录类别映射、输入波段、位深归一化、图像尺寸、置信度和 IoU 阈值。
- 除总体指标外，报告不同工况分组指标和失败案例。

## 发布门禁

- 全量自动测试通过。
- 金标准数据输出在预设容差内。
- `pip check` 无依赖冲突。
- 内置模型哈希与 `data/models/model_registry.json` 一致。
- 导出文件与 manifest 哈希一致。
- 版本标签、Git 提交和实验记录一致。
