# 研究、算法、界面与田间验证统一流程

本文档是 `ALIGN` 课题范围、算法顺序、界面顺序和田间证据边界的统一入口。其他开发文档出现简化表述时，以本文档和 `docs/DECISIONS.md` 的对应决策为准。

## 1. 研究对象与目标

`ALIGN` 服务于宽窄行再生稻无人自主收获收割机的对行机收路径规划。研究链从无人机正射影像感知开始，经过种植带实例分割、作业带确定、作业中心线生成和农机约束路径规划，最终把路径导入无人自主收获收割机终端开展田间作业，并以实际执行记录和作业后碾压调查评价结果。

软件系统是研究方法的实现与证据载体，不单独构成一项与论文主线并列的“界面开发研究”。

## 2. 算法顺序与界面顺序

### 2.1 算法内部顺序

`作业带确定 → 作业中心线生成`

- 实例分割和掩膜规整完成后，系统依据行带宽度、主方向、连续性、田块边界和割台宽度确定可规划作业带。
- 宽窄行区以完整四行宽行带作为作业带；窄行只保留为识别和分类证据，不直接生成作业线。
- 等距种植区按割台有效作业宽度划分作业带。
- 只有作业带确定完成后，才允许从作业带生成候选作业中心线。

### 2.2 用户界面顺序

`生成中心线 → 选择中心线 → 设置起点/终点 → 路径规划`

- “生成中心线”读取算法已经确定的作业带，生成并显示整田候选中心线目录。
- “选择中心线”只决定哪些候选中心线进入本次正式路径；取消勾选后，该线立即隐藏且不参与规划。
- 起点用于选择首条作业线及进入方向；终点或卸粮点按当前服务点模式参与末段参考或协议投影。
- “路径规划”对选中的中心线统一排序、确定行进方向并连接田头转弯。

两种顺序描述的对象不同：前者描述算法依赖关系，后者描述用户可见操作。作业带确定是“生成中心线”之前的内部前置状态，不需要新增“选择作业带”按钮，因此二者不存在冲突。

## 4. 术语边界

- **种植带**：由影像分割和几何重建得到的作物空间结构，是识别证据。
- **作业带**：综合种植带结构、割台宽度、连续性和田界后确定的可作业空间，是中心线生成的直接依据。
- **作业中心线**：作业带内用于引导无人收获机对行行驶的候选基准线；被操作员选中后成为本次路径的主作业线。
- **田头走廊掩膜**：用于田头作物证据和转弯空间校验的辅助图层，不是独立的“通行廊道生成”研究任务，也不替代作业中心线。
- **掩膜规整**：对实例分割并集进行方向估计、碎片聚合、黏连分离、断裂修复和残差分层，使其形成可解释的种植带几何。论文中优先使用“掩膜规整与种植带重建”，避免把“正则化”误解为单一数学惩罚项。

## 5. 软件证据与田间证据分层

1. `align.paper-experiment.v1` 是离线掩膜阶段消融工具。默认计划只比较真实存在的掩膜处理中间层，用于说明掩膜规整各阶段的作用；它不代表整篇论文只研究掩膜处理。
2. `align.field-trial-package.v1` 保存源影像预览、原始/处理后掩膜、完整路径、导入候选文件、manifest、诊断包和软件验证结果。它证明软件链及文件关联可追溯，但不等于目标终端已接收或无人收获机已成功自主执行。
3. 终端导入结果、实际自主执行轨迹、人工接管或中断记录和作业后碾压调查属于田间实验证据，必须按生育期或田块独立归档。
4. `planar_rigid_footprint_v2` 产生的是二维理论履带扫掠与几何覆盖指标。它不能替代实际碾压面积、作物损伤、产量变化或车辆跟踪误差实测。
5. 系统实现四种固定转弯方式并校验所选路径，不自动开展转弯策略优化。只有论文另设冻结输入、重复和统计对照时，才能比较不同策略的优劣。

- 开发文档中的“自动实验包”“田间试验资料包”和“实际田间试验”必须分层表述。
- 论文结构应围绕真实研究链组织；软件界面只作为方法实现、数据管理和田间执行支撑，不单独扩写成系统开发章节。
