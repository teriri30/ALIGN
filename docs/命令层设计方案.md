# ALIGN 命令层完整实施方案（Agent 可操作系统）

- 版本：v1 设计定稿（2026-11-11）
- 状态：**阶段 1 完成**（2026-11-11 阶段 0 定稿获用户批准；`src/align_cli.py` 主流程 12 条 + run-batch 经真实影像 5 轮实测迭代全部跑通，R2 一致性验证 PASS——CLI 与界面装配链在同输入下段结构/指标/指纹完全一致，见文末「阶段 1 验收记录」）
- 性质：本方案只新增**入口层**，不修改任何已验证的核心算法、状态机门禁、缓存格式与导出格式（遵守系统冻结纪律：已验证机制不为新增能力而改动）

## 一、目标

在 Agent（Hermes / Claude 等）里分发命令即可完成 ALIGN 的全部操作——不打开界面、不手动点按钮；同一输入下，Agent 命令产出与人在 GUI 手点**完全一致**。

人需要提供的输入只有两样：

- `--tif`：正射影像路径；
- `--field`：田块边界——`full-frame`（影像即田块）、多边形 geo.json（人的判断变成数据）、或从缓存继承（同田块免重画）。

其余全部走默认：模型从 model_registry.json 自动选、推荐起点、作业线=过滤后全用、套圈转弯、终点/卸粮点/禁行区选填缺省不阻塞。

**默认即实验（用户口径 2026-11-11）**：默认农机参数（割幅 2.00 m / 履带宽 0.35 m / 轨距 1.30 m）就是实机实测情况；命令层把这组默认值的来源记为 `user_measured`，不设 provenance 边界。

## 二、五条铁律

1. **单一引擎**：GUI 与命令层调用同一批领域函数（inference / mask_processor / row_geometry / path_planner / footprint_planner …），禁止复制任何业务逻辑。一致性不是靠测试"试"出来的，是靠同一段代码保证的。
2. **不动内核**：算法、状态机、`.hillcache` 缓存格式、导出格式全部不动；命令层只是新入口。
3. **命令粒度 = 按钮/菜单级**：一条命令对应一个界面动作，不暴露内部函数（接口面小，系统演进不易破坏契约）。
4. **失败的样子也要一致**：门禁不过时命令层同样 fail-closed——不生成路径、返回失败原因与诊断建议，绝不硬造结果。
5. **不做"Agent 点界面"**：不模拟鼠标键盘；界面与命令是平行前端。

## 三、总体架构

```
前端外壳（均不含业务逻辑）
 ├─ PySide6 GUI（现有；不改也能共存，薄壳化可选、放最后）
 ├─ CLI：python src/align_cli.py <命令> [选项]（人/脚本/Agent）
 └─ MCP server：src/align_mcp.py（Agent 原生调用，阶段 4）
        ↓ 三个外壳都只做一件事：把「命令 + 参数」交给命令层
命令层（唯一新增的大件）
   命令注册表：每条命令 = 名称 + 参数 + 前置门禁 + 执行体 + 产物契约
   逐命令落 manifest.json；命令边界同步强写状态
        ↓ 执行体调用的就是
状态内核（现有，不重写）
   AppState + 状态机门禁 + 领域函数
   缓存 .hillcache/<hash>/（源码运行）或 %LOCALAPPDATA%\ALIGN\cache（打包运行）
   产物：$PATH TXT / 快照 PNG / 诊断 JSON
```

**依赖与运行规则（硬约束）**：

- 命令层只 `import` src/ 下的领域模块，**禁止 import pyside6_app**（阶段 1 用 grep 断言钉住）；
- 命令实现参照 `band_evaluation.py` / `smoke_full_pipeline.py` 的离线模式：领域函数直接调用、必要处镜像 worker 编排，**不启动 Qt 事件循环**；
- GUI 与 CLI **共用同一缓存根**（同一运行形态下）：Agent 跑到一半停掉，人打开界面能从缓存恢复出同样现场；反过来 GUI 做到一半，Agent 也能接着跑；
- **进程形态**：CLI 每条命令一个独立进程、跑完退出，现场全靠缓存持久化（进程重启=缓存恢复，正好复用现有 restore 链）；不做常驻后台服务，Agent 侧的常驻由 MCP server 承担；
- 新增文件落点：`src/align_cli.py`（阶段 1）、`tests/test_cli_contract.py`（阶段 3）、`docs/AGENT.md`（阶段 3）、`src/align_mcp.py`（阶段 4）；命令实现多时可拆 `src/commands/`。

## 四、命令契约

### 4.1 通用约定

- **调用**：`python src/align_cli.py <命令> [选项]`，工作目录任意（模块自举 src 路径，与 band_evaluation.py 同模式）。
- **人读输出**：stdout（强制 UTF-8）——阶段日志 + 一行结论。
- **机读输出**：每个 run 一个输出目录，含 `manifest.json`：版本、命令名、全部参数、产物文件清单（含哈希）、关键数字（带数 / 段数 / 导出点数 / 门禁结果）、失败原因。
- **退出码**：`0` 成功；`2` 前置门禁未满足（附 blocker 原文 JSON）；`3` 执行失败（附 traceback）；`4` 参数错误。
- **落盘**：命令结束时同步强写（不走界面的延迟合并写）；每一步的现场都留在缓存里。

### 4.3 重点命令详述

**run-batch（默认链，最重要）**

```
python src/align_cli.py run-batch --tif data/tif/result.tif --field full-frame [--out 输出目录] [--stop-after segment]
```

= `set-field → load-model(自动) → segment → process-mask → gen-worklines → select(--default) → set-entry(--auto) → plan → export-txt` 的串联。`--stop-after <命令名>` 在任一步停住；任一步失败立即停并打印该步诊断——不做静默降级、不伪造结果（沿用 smoke 脚本纪律）。

**query-status（Agent 的眼睛）**

返回每步状态 + blocker 原文 + 产物路径。blocker 文案直接复用界面 task_state 体系（它本来就是写给"不知道下一步的人"看的）。Agent 拿到 blocker 就知道还缺什么，再决定下一条命令。

**export-txt**

产物验收沿用全链路纪律：回读文件——`is_file()`、非空、首行 `$PATH,0,`、末行 `$INFM`、统计 `$PATH` 条数；单文件 ≤50 航点、超出自动分段编号；CSV/KML/JSON 辅助导出走同一命令的可选开关。

## 五、关键机制

1. **断点续跑（硬验收）**：分步跑（`--stop-after` 分段 + `restore` 续跑）与一次跑完，最终产物**逐字节一致**（哈希对比）。现场即缓存，不另造状态存储。
2. **乱序防护**：Agent 发错顺序 = 人点错顺序——blocker 就地提示 + `_invalidate_analysis_from` 失效级联清下游，语义照搬界面，不发明新规则。
3. **双入口一致性（防漂移闸门）**：契约测试——同一输入，离屏（`QT_QPA_PLATFORM=offscreen`）跑 GUI handler 路径 vs CLI 路径，产物哈希 + 关键数字逐项比对；进全量测试，用户改系统期间尤其重要。
4. **长任务**：识别 / 规划为分钟级，命令独立进程跑；中断后 `restore` 续跑，不重跑已完成步骤（缓存产物优先于标记的既有纪律）。
5. **并发保护**：同一缓存目录加锁文件；GUI 与 CLI 同时操作同一项目时后到者拒绝并提示（阶段 2）。
6. **默认链与细粒度并存**：默认一条 `run-batch` 直通 TXT；细粒度命令全部保留，供"分发足够细致的指令"做特殊控制。
