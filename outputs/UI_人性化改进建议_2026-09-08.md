# reUI 系统 UI 人性化改进建议

**生成日期**：2026-09-08  
**目标**：使系统操作符合人类直觉，简单易用

---

## 🔴 **高优先级：影响核心使用体验**

### **1. 人工编辑路径的入口不够显眼**

**现状问题**：
- 用户需要点击"路径结果"卡片中的某个按钮才能进入编辑模式
- 第一次使用时，用户不知道"如何手画路径"

**用户期望**：
- 主工具栏或明显位置有"手动编辑路径"按钮
- 按钮图标用铅笔✏️或手绘图标

**改进建议**：
```python
# 在 TopToolbar 或 TaskPanel 顶部增加明显按钮
btn_manual_edit = QPushButton("✏️ 手动编辑路径")
btn_manual_edit.setToolTip("不依赖AI识别，直接在画布上手画作业路线")
btn_manual_edit.setStyleSheet("""
    QPushButton {
        background: #4C8C7C;  /* 与其他功能按钮统一色系 */
        color: white;
        border-radius: 6px;
        padding: 8px 16px;
        font-size: 13px;
        font-weight: 600;
    }
    QPushButton:hover {
        background: #5E9C8C;
    }
""")
```

**位置建议**：放在左侧任务清单顶部，"路径规划"步骤下方，标注"（可跳过自动规划）"

### **2. 任务清单的线性流程不够灵活**

**现状问题**：
- 任务清单严格按"影像导入→田块圈选→AI识别→...→路径规划"线性流程
- 但用户可能想**直接手画路径**（跳过AI识别、掩膜处理、中心线生成）
- 当前若没有完成前置步骤，"路径规划"和"编辑路径"都是灰色不可用

**用户期望**：
- "手动编辑路径"应该独立于自动规划流程
- 最小前提：只需要**影像导入** + **田块圈选**，就能手画路径

**改进建议**：
在 `task_state.py` 的 `derive_task_statuses` 中增加逻辑：
```python
# 新增：手动编辑路径的独立入口
manual_edit_ready = bool(image_loaded and field_done)

if manual_edit_ready:
    statuses["manual_edit"] = TaskStatus(
        "available",
        "可跳过自动规划",
        action="手画"
    )
```

并在 `TASK_DEFS` 中增加：
```python
{
    "id": "manual_edit",
    "label": "手动编辑路径",
    "hint": "不依赖AI识别，直接在画布上手画作业路线（只需完成影像导入和田块圈选）",
    "color": "#9B59B6",  # 紫色，与自动规划区分
    "action": "手画"
}
```

### **3. 路径验证失败的提示过于技术化**

**现状问题**：
- 验证失败时显示："track_outside_field_pct=5.2% exceeds limit=2.0%"
- 普通用户看不懂 `track_outside_field_pct` 是什么

**用户期望**：
- 用通俗语言说明问题：**"履带越出田界 5.2%（超过限制 2%）"**
- 红色显示硬错误，黄色显示软警告
- 提供修改建议："请调整路径，避免越界"

**改进建议**：
在 `footprint_planner.py` 的 `add_issue` 函数中增加翻译字典：
```python
ISSUE_TRANSLATIONS = {
    "track_outside_field_pct": "履带越出田界",
    "track_forbidden_overlap_pct": "履带进入禁行区",
    "track_core_overlap_pct": "履带碾压作物核心区",
    "planned_target_geometric_coverage_pct": "割刀覆盖率",
    "rolling_canopy_pct": "预计碾压率",
}

def add_issue(description: str, severity: str = "error"):
    # 翻译技术指标名称
    for tech_term, user_term in ISSUE_TRANSLATIONS.items():
        if tech_term in description:
            description = description.replace(tech_term, user_term)
    
    # 增加修改建议
    suggestions = {
        "履带越出田界": "→ 请调整路径，或扩大田块圈选范围",
        "履带进入禁行区": "→ 请拖动作业线避开禁行区",
        "割刀覆盖率": "→ 覆盖率略低，可调整作业线位置优化",
    }
    for keyword, suggestion in suggestions.items():
        if keyword in description and severity == "warning":
            description += f" {suggestion}"
    
    issues.append({"description": description, "severity": severity})
```

### **4. 起点/终点/卸粮点的操作逻辑不够直观**

**现状问题**：
- 当前流程：点击"起点（必选）"按钮 → 在画布点击布设 → 点击"确认"按钮锁定
- 用户反馈："我点了起点按钮后，不知道下一步要干嘛"
- "确认"按钮的含义不明确（是确认位置？还是确认要使用起点？）

**用户期望**：
- **一键布设**：点击"设置起点"按钮 → 直接在画布点击 → 自动锁定，无需再点"确认"
- 若要调整，点击"调整起点"按钮，进入拖动模式

**改进建议**：
```python
# 简化流程
def _on_set_entry_point_click(self):
    # 旧流程：self.state.entry_exit_mode = True (需要再确认)
    # 新流程：直接进入"点击画布即完成"模式
    self.log_panel.info("请在画布上点击起点位置（点击后自动完成）")
    self._one_click_mode = "entry"  # 标记一键模式
    self.lbl_status.setText("📍 点击画布设置起点")

def _on_viewer_click(self, x, y):
    if self._one_click_mode == "entry":
        self.state.entry_point = (x, y)
        self.state.entry_point_locked = True  # 直接锁定
        self._one_click_mode = None
        self.log_panel.info("✅ 起点已设置")
        self.lbl_status.setText("起点已完成，可继续规划路径")
        self._refresh_ui()
```

**UI 按钮文字改进**：
- 旧："起点（必选）" → 状态："推荐待确认" → 按钮："确认"
- 新："起点（必选）" → 状态："待设置" → 按钮："点击画布设置"
- 设置后："起点（必选）" → 状态："✅ 已完成" → 按钮："调整"

## 🟠 **中优先级：提升使用流畅度**

### **5. 中心线选择界面与画布联动不够明显**

**现状问题**：
- 左侧任务清单有复选框勾选中心线
- 画布上也有中心线显示
- 但两者不联动高亮：勾选某条中心线时，画布上对应的线没有特殊高亮

**改进建议**：
```python
# 勾选某条中心线时，画布上该线闪烁或加粗显示 2 秒
def _on_centerline_checkbox_changed(self, centerline_id, checked):
    self.state.selected_centerline_ids.append(centerline_id) if checked else ...
    
    # 新增：画布高亮
    if checked:
        self._highlight_centerline_on_canvas(centerline_id, duration_ms=2000)
        self.log_panel.info(f"已选择中心线 {centerline_id}，画布上已高亮显示")
```

### **6. 套圈收割策略的选择位置不够显眼**

**现状问题**：
- 转弯策略选择器藏在"高级设置"或"农机参数"对话框里
- 但你明确说"目前只需要套圈模式"
- 普通用户可能不知道要去哪里选

**改进建议**：
1. **默认策略改为套圈**：
```python
# config.py
DEFAULT_TURN_STRATEGY = "contour"  # 旧值可能是 "bow" 或 "auto"
```

2. **在路径规划卡片直接显示当前策略**：
```python
# 在"路径规划"任务卡片下方显示
lbl_strategy = QLabel("当前策略：套圈收割（推荐）")
lbl_strategy.setStyleSheet("color: #666; font-size: 11px;")
```

3. **若要切换，点击"高级"按钮**：
```python
btn_advanced = QToolButton()
btn_advanced.setText("高级...")
btn_advanced.setToolTip("切换转弯策略（一般情况下无需调整）")
```

### **7. 回退操作的确认对话框过于冗长**

**现状问题**：
- 点击"回退"按钮时，弹出对话框显示：
  > "将回退到"XX"之前。\n\nXX及其后的YY、ZZ、WW都会清除；AA保留。\n\n此操作可通过撤销恢复（若当前会话未关闭）。"
- 对于频繁操作的用户，每次都要读一遍长文本很烦

**改进建议**：
```python
# 简化对话框文字
def _on_rollback_task(self, task_id):
    label = TASK_LABELS.get(task_id, task_id)
    reply = QMessageBox.question(
        self,
        "确认回退",
        f"将回退到"{label}"之前，后续结果会清除。\n\n"
        f"（可通过"编辑→撤销"恢复）",
        QMessageBox.Yes | QMessageBox.No,
        QMessageBox.No
    )
    if reply == QMessageBox.Yes:
        self._do_rollback(task_id)
```

**更激进的方案**：增加"不再提示"选项
```python
chk_dont_ask = QCheckBox("不再提示（直接回退）")
# 若勾选，下次直接执行回退，无需确认
```

### **10. 操作日志的用语优化**

**现状问题**：
- `self.log_panel.info("缓存已恢复；请在任务清单中点击'生成中心线'。")`
- 用语过于正式，像是软件在"命令"用户

**改进建议**：
- 改为更友好的提示语气：
  - 旧："请在任务清单中点击'生成中心线'"
  - 新："接下来可以点击"生成中心线"继续"
  - 或："已恢复缓存，可继续上次进度"
